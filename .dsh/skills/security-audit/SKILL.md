# security-audit · 代码安全审计

四类目标，前两类靠脚本，后两类靠人：

| 类别 | 查什么 | 手段 |
|---|---|---|
| 凭证泄露 | 源码/注释里的密码、Token、私钥、带密码的连接串 | 脚本 |
| SQL 注入 | f-string、字符串拼接、`%` / `.format()` 拼进 SQL | 脚本 + 人工看 ORM 的 raw 分支 |
| 配置明文 | `.env` / `yaml` / `json` / `ini` 里的明文口令 | 脚本 |
| 其他高危 | eval / pickle / shell=True / 关证书校验 / CORS 全开 / 弱哈希 / XSS | 脚本先扫，人工补 |

## 1. 第一步：跑扫描器

脚本：`.dsh/skills/security-audit/scripts/security_scan.py`
绝对路径：`D:\lanchain rag项目\.dsh\skills\security-audit\scripts\security_scan.py`

```powershell
chcp 65001 | Out-Null
$env:PYTHONIOENCODING = "utf-8"

& ".\.venv\Scripts\python.exe" ".dsh\skills\security-audit\scripts\security_scan.py" <目录或文件> [--json] [--min-severity=中]
```

本项目扫描范围：`backend\app`、`backend\tests`、`frontend\src`、`scripts`、`tools`。不要扫 `data\`（含 Chroma 向量与上传原件）、`node_modules\`、`.venv\`、`frontend\dist\`。

### 本项目已接受的例外（不算 P0，但报告里要写明理由）

| 项 | 位置 | 为什么接受 |
|---|---|---|
| 内置管理员初始口令 `admin/123456` | `backend\app\config.py`、`scripts\seed_demo.py` | 需求明确指定；README 与启动脚本都提示首次登录后改密；仅本地演示部署 |
| 演示账号 `demo/demo123` | `scripts\seed_demo.py` | 演示数据脚本，非生产路径 |
| `.env` 中的 `DASHSCOPE_API_KEY` | 仓库根目录 | 已被 `.gitignore` 排除，只在运行时读取；`start.bat` 检查其存在 |

这三项在报告里写「已接受例外」，不要写成「未发现问题」。

- 只读扫描，**不会执行**被扫描项目的任何代码。
- 自动跳过 `.git` / `.venv` / `node_modules` / `dist` / `build` / `__pycache__`。
- **输出已打码**：凭证只保留首尾各 2 个字符，其余 `***`。看到 `gh***yz` 是正常现象，不是脚本坏了。
- 退出码：0 = 无高危；1 = 有高危；2 = 参数错误。

**规则编号**：`SEC-*` 凭证、`SQL-*` 注入、`CFG-*` 配置明文、`RISK-*` 其他高危。

**扫描器查不了的**（必须人工）：
- ORM 里 `text()` / `raw()` 之外的自定义 SQL 拼装
- 越权（IDOR）：接口有没有校验资源属于当前用户
- 反序列化、路径穿越、SSRF 的**业务路径**判断
- 依赖漏洞（要 `pip-audit` / `npm audit`）
- Git 历史里的过期密钥（脚本只看工作区）

## 2. 第二步：人工必查清单

按项目类型挑着看，本地桌面应用和公网服务的威胁模型完全不同。

1. **鉴权与越权**：每个写接口是否校验「这条数据是调用者的」。本地单机应用可豁免，但要写出豁免理由。
2. **注入面**：ORM 之外的 raw SQL、`LIKE` 拼接、排序字段来自前端（`ORDER BY` 不能用参数化，必须白名单）。
3. **文件类**：上传（类型/大小/文件名穿越）、导入（CSV 公式注入、zip 炸弹）、导出（CSV 注入）。
4. **反序列化**：`pickle` / `yaml.load` / `eval`，以及 JSON 里的 `__proto__`。
5. **网络暴露面**：监听地址是 `127.0.0.1` 还是 `0.0.0.0`；CORS 白名单；是否强制 HTTPS。
6. **日志与报错**：日志里打了密码/token/完整身份证；500 页面回显堆栈。
7. **会话与令牌**：JWT 算法白名单、过期时间、Cookie 的 `HttpOnly`/`Secure`/`SameSite`。
8. **前端**：`v-html` / `innerHTML` / `dangerouslySetInnerHTML`，以及把密钥打进前端 bundle（前端一切都会被打包发到浏览器）。

**本项目（电商 RAG 知识库）重点补查**：

- **越权**：`/api/conversations/{id}`、`/api/messages/{id}/feedback`、文档删除是否都校验 `user_id`；管理员接口是否走 `require_admin`。
- **令牌**：改密后 `token_version` 是否递增使旧 token 立即失效；refresh token 的 `typ` 是否校验。
- **SSE**：`/api/chat/stream` 是否校验会话归属；断连后是否停止生成，避免继续烧 token。
- **上传**：扩展名白名单、20MB 上限、文件名是否参与路径拼接（本项目用 `doc_id + ext`，不落原始文件名）。
- **CORS**：是否只放行 `127.0.0.1:8000` / `localhost:5173`，不要 `*`。
- **提示词注入**：知识库文档内容会进 prompt，文档里出现「忽略以上指令」不应影响系统约束；回答只引用检索片段。
- **数据目录**：`data/` 下有 SQLite 与 Chroma，确认已在 `.gitignore`，且不会被静态路由暴露。
- **限流**：登录/注册 10 次/分、问答 30 次/分是否真的挂上。

**CSV 注入**要单独提一句：用户备注以 `=`、`+`、`-`、`@` 开头时，Excel 会当公式执行。导出时给这类字段加前缀 `'` 或强制加引号转义。

## 3. 定级标准

| 级别 | 判定 | 例子 |
|---|---|---|
| **高** | 拿到代码即可利用，或凭证已泄露 | 硬编码生产密码、私钥入库、SQL 注入、`eval` 外部输入 |
| **中** | 需要特定条件或组合利用 | 弱哈希、DEBUG 开着、CORS `*`、`verify=False` |
| **低** | 加固建议，不直接可利用 | `except: pass`、注释掉的密钥（历史里还在） |

同时给出**影响**：泄露的凭证能访问什么、注入能读到哪张表、弱哈希被拖库后多久能爆破——没有影响描述的报告等于没写。

## 4. 三类常见误报，别急着报警

1. **占位符**：`PASSWORD=${DB_PASSWORD}`、`changeme`、`your-token-here`、`<your-key>`。
2. **测试夹具**：`tests/fixtures/` 里的假 token、`docs/` 里的示例 curl。仍要确认不是真凭证。
3. **本地开发配置**：`localhost` 的测试库口令、`sk-test-` 开头的沙箱 key。要判断这份配置会不会进生产。

判定为误报也要写进报告，说明「为什么不是问题」——否则下一个人还得重新判断一遍。

## 5. 修复原则（进入修复模式时）

1. **先止血再清理**：确认是真凭证 → 立刻去平台**吊销/轮换**，再改代码。只改代码不吊销等于没修。
2. **凭证只从环境变量或密钥服务读**，代码里出现 `os.environ` 是可接受的写法。
3. 配置文件进 `.gitignore`，仓库里只留 `.env.example`（值是占位符）。
4. **Git 历史要单独处理**：`git log -S "泄露的字符串"` 确认影响范围；历史里的密钥必须当作已泄露。
5. SQL 一律参数化：`text("... WHERE id = :id")` + `{"id": value}`；`ORDER BY` / 表名用白名单，不接用户输入。
6. 修完**复跑扫描器**（高危归零）并跑项目测试（证明没改坏行为）。
7. 报告里写「改前 → 改后」，并且**不要把修复后的真实凭证写进报告**。

## 7. 禁止事项

- **不执行 exploit**：不构造真实攻击请求打生产/测试环境，不 `curl` 带 payload。
- 不在报告、聊天、日志里贴完整凭证或私钥。发现真实泄露，最多写「已打码」+ 位置。
- 不自动轮换/删除密钥、不改云平台配置——这类操作必须由人执行。
- 不把「扫描器 0 命中」当成「没有安全问题」：脚本只覆盖已知模式。
- 不对第三方库源码、`node_modules`、构建产物做审计。
- 不因为「本地应用没人攻击」就跳过检查——要把威胁模型写清楚再豁免。
