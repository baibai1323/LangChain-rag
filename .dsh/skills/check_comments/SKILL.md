# check_comments · 注释质量检查

三条验收标准，缺一条都算不合格：

| 维度 | 标准 | 谁来判断 |
|---|---|---|
| **数量** | 每 10 行有效代码至少 3 行注释（密度 ≥ 30%），每个函数都有 docstring | 脚本自动算 |
| **一致** | 注释描述的行为 = 代码实际行为 | 人/AI 逐条比对 |
| **可读** | 刚学编程的人能顺着注释读懂这段代码在干什么 | 人/AI 按 rubric 打分 |

脚本管「数量」，AI 管「一致」和「可读」，三者都过才算合格。

本项目建议的体检范围（按优先级）：

| 范围 | 说明 |
|---|---|
| `backend\app` | 主目标：FastAPI 路由、SQLAlchemy 模型、RAG 服务 |
| `backend\tests` | 测试代码也要能读懂，密度要求可放宽到 20% |
| `frontend\src` | 只扫 `.vue` 的 `<script>` 与 `.ts`，模板不计入 |

本项目分级口径（与 `security-audit` 统一）：

- **阻断级只看真问题**：注释与实现相反、docstring 描述与行为不符、docstring 里的参数在签名里不存在、把密钥/口令写进注释 → **P0**；`backend\app` 新增公共函数完全无 docstring 且逻辑不直观 → **P1**。
- 扫描器报的「密度 < 30%」「函数没有 docstring」「长函数体内零注释」在本项目统一记为**提示（P2）**：只写进报告，不阻断提交。理由是本项目以 docstring 为主要说明手段，脚本按行统计 `#` 会系统性低估密度；为了过闸批量补“获取用户”这类空话注释，反而制造维护噪音。
- `backend\tests` 密度只做参考，不单独立项；测试名写清楚即可。
- `frontend\src` 注释不足记 **P2**：Vue 模板天然拉低密度，不阻断提交。
- `scripts\`、`tools\` 按 20% 放宽，它们是内部工具，不对外。

- 支持 `.py`（AST 精确分析）与 `.js/.ts/.vue`（行扫描近似，报告里标 `kind: js`，结论要保守）。`.vue` 只统计 `<script>` 段，`<template>`/`<style>` 不计入有效行，避免模板越长密度越低的失真。
- 目录会递归，自动跳过 `.venv` / `node_modules` / `__pycache__` / `dist`。
- 退出码：0 = 无 P0/P1；1 = 有；2 = 参数错误或没找到文件。
- 报告太长时用 `--json` 拿结构化结果再筛。

**脚本能查**：注释密度、函数缺 docstring、长函数（正文 ≥15 行）体内零注释、docstring 写了签名里没有的参数、疑似被注释掉的代码、无署名的 TODO、过短的空洞注释、魔法数字、嵌套 ≥5 层。

**脚本查不了**：注释说的和代码做的是不是一回事——必须人看。

## 2. 一致性审查（AI 逐函数比对）

每个函数都做一遍：先读注释，再读代码，专挑这六种翻车：

1. **参数/返回值对不上**：docstring 写「返回 dict」，实际返回 list；写着 `page_size`，签名里是 `limit`。
2. **阈值漂移**：注释说「最多 100 条」，代码是 `[:200]`；改了常量没改注释。
3. **行为已变，注释没跟**：函数早改成软删除，注释还写「物理删除」。
4. **复制粘贴残留**：A 函数的说明原封不动留在 B 函数上，出现不属于它的变量名。
5. **描述与实现相反**：注释说「跳过空行」，代码 `if line: continue` 跳的是非空行。
6. **承诺了没做的事**：注释写「失败会重试三次」，代码里没有重试。

命中任一条 → **P0**。这比密度不够更严重：错的注释比没注释更害人。

## 3. 小白可读性 rubric（8 条，每条 0/1 分）

把代码想象成给一个只会基本语法、不懂业务的人看：

1. **命名表意**：`total_cents` 而不是 `t`；没有 `tmp1`、`res2`、`data3`。
2. **魔法数字有解释**：`if len(errors) < 50` 旁边说明为什么是 50。
3. **函数只做一件事**：正文 ≤ 40 行、嵌套 ≤ 4 层；超了说明该拆。
4. **业务术语有注解**：「月结」「回收站」「兜底分类」这类词第一次出现要有一句解释。
5. **控制流平直**：没有三层以上 if 嵌套、没有超长的 `and/or` 链。
6. **错误信息能看懂**：不是 `raise ValueError("invalid")`，而是 `raise ValueError("金额必须大于 0")`。
7. **隐式行为有提示**：自动补零、默认值、单位换算（元→分）这类「悄悄做的事」必须写出来。
8. **注释解释「为什么」，不复述「是什么」**：`# i 加一` 是噪音，`# 跳过表头行，导入模板第一行是列名` 才是注释。

≥6 分算可读；≤5 分 → P1。

---

## 4. 分级与处置

| 级别 | 含义 | 处置 |
|---|---|---|
| **P0** | 密度不达标 / 注释与代码矛盾 | 必须改，改完复跑脚本 |
| **P1** | 缺 docstring、长函数无注释、可读性 ≤5 分 | 本轮改 |
| **P2** | 魔法数字、空洞注释、嵌套过深、TODO 无署名 | 记录，攒着改 |

密度是**文件级**指标，允许局部豁免，但报告里必须写明理由：纯常量表、自动生成代码、单行转发函数。豁免不是免死金牌——整个文件都在豁免，那就是没写注释。

---

## 5. 修复模式（用户要求「顺便改」才进入）

按顺序执行：

1. **只加注释、只改注释，不碰任何逻辑**。除了空行与缩进，代码一个字符都不许动。
2. docstring 用中文，三段式：**做什么 / 参数含义 / 返回什么**；纯内部小函数可以只写一句。
3. 块内注释写「为什么这么做」，放在对应代码**上方**；行尾注释只用于短说明。
4. **禁止**：`# 定义一个变量`、`# 循环`、`# 返回结果`、把代码翻译成中文的废话。
5. 复杂分支、边界条件必须注释：为什么是这个顺序、为什么特判、这个魔数从哪来。
6. 改完**必须复跑**：脚本密度达标 + 项目原有测试全绿。注释不该改变行为，测试红了说明改坏了。
7. 报告里给「改前 → 改后」密度对比，别只说「已优化」。

## 7. 禁止事项

- 不要为凑密度灌水注释（`# 循环开始`）。30% 是下限，不是目标。
- 不要用注释掩盖烂代码：需要三行注释才能讲清的十层嵌套，该重构。
- 注释里不写会过期的信息（具体行号、文件里第几个函数）。
- 不为「注释达标」改代码逻辑。
- 不对自动生成的文件（migrations、protobuf 产物）做体检。
- 不把 `.vue` 模板部分的 HTML 计进注释密度。
